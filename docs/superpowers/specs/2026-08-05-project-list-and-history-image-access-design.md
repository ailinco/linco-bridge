# 项目列表与历史图片访问设计

## 目标

1. `/project` 返回全部已经发现、校验并去重的项目，不再只返回前 20 条。
2. App 同步当前绑定项目的 Codex 历史后，可以取回该历史中明确引用的本地临时图片。
3. 不开放整个系统临时目录，不扩大其他项目或其他会话的文件读取权限。

## 根因

`knownProjectCandidates()` 在候选项目完成校验和去重后固定执行 `slice(0, 20)`，所以 `/project` payload 最多包含 20 个项目。

历史图片的结构化 `localPath` 已经到达 App，并被转换为现有图片 marker。App 随后调用 `/im/bridge-files/preview`，服务端通过桥接发送 `/get <localPath>`。Codex 剪贴板图片通常位于系统临时目录，不属于插件当前允许的工作区、项目、运行目录或附件目录，因此 `/get` 返回 `outside_allowed_roots`，marker 最终停留在本地路径并显示占位图标。

## 设计

### 项目列表

`knownProjectCandidates(session, options)` 支持可选的结果数量限制：

- `/project` 不传限制，返回全部规范化候选项目。
- `/get` 继续显式使用原来的 20 个已知项目根目录限制，避免项目列表扩容自动扩大文件读取范围。
- 项目发现过程已有的文件扫描上限继续保留，它们用于控制本地扫描成本，不是 `/project` 的展示数量限制。

### 当前项目历史文件授权

插件在生成 history payload 后，从 `round.user.files` 和 `round.assistant.files` 中提取已经通过历史文件元数据校验的 `localPath`，登记到当前桥接会话的历史文件授权中。

授权记录包含：

- 当前 Agent 类型。
- 当前绑定的 Agent Session ID。
- 当前项目规范化绝对路径。
- 精确文件绝对路径集合。

授权规则：

- 只接受 payload 中实际返回的绝对文件路径，不接受目录。
- `/get` 必须同时匹配当前 Agent Session ID、当前项目和精确文件路径。
- 切换项目或 Agent Session 时，旧授权不再有效。
- 同一身份的分页历史可以合并授权，集合设置有限上限，防止会话内存无限增长。
- 即使精确路径命中，仍必须通过现有的普通文件、存在性、大小、隐藏路径、危险扩展名和软链接校验。
- `/get` 响应和历史 payload 继续禁止直接携带未请求的文件正文；只有显式预览请求才读取文件。

### 数据流

1. 插件解析当前项目、当前 Agent Session 的历史。
2. 插件构造 metadata-only history payload。
3. 插件把 payload 中的精确文件路径登记到当前会话授权。
4. App 导入 marker 并调用现有 bridge preview 接口。
5. 服务端发送现有 `/get <localPath>`。
6. 插件确认项目、Agent Session 和精确路径都与授权一致，再执行原有文件安全校验和读取。
7. 服务端上传 OSS，App 用远端 URL 替换 marker。

## 兼容性

- 不含图片的历史行为不变。
- 旧插件没有精确授权，App 保留原来的失败降级行为。
- 旧 App 忽略可选 `files`，不会触发新增读取。
- 工作区、运行目录、附件目录和原有项目根目录的 `/get` 行为不变。
- 管理后台不参与该链路，不修改。

## 测试

- 超过 20 个合法项目时，`/project` payload 返回全部项目。
- `/get` 的已知项目根目录范围仍保持原来的显式限制。
- 当前项目、当前 Agent Session 历史中登记的临时图片可以读取。
- 同一路径在其他项目、其他 Agent Session 或未登记状态下被拒绝。
- 项目或 Agent Session 切换后旧路径被拒绝。
- 精确授权文件仍受大小、隐藏路径、危险扩展名和软链接规则约束。
- 现有项目选择、历史同步、普通文件读取和图片同步测试保持通过。
